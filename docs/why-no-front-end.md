# Why the planning base has no front end

The weekly decision is who can take the work and what no longer fits. A database and a coding agent answer that without maintaining a scheduling application. Ask for daily conflicts, a staffing shortlist, a project plan or a meeting pack.

A screen gives drag-and-drop timelines, live multi-user edits, phone access, offline capture and time-of-day scheduling. This base does not provide those. Its HTML views are read-only snapshots, and they must be regenerated after records change. Local mode supports one process. It suits a planner-led weekly process. If the team needs an interactive daily scheduler, agree that requirement with Enterprise DNA before choosing the free base. That front end and the required connections belong in the customised version.

brand.json sets the business name, logo URL, colours and footer. npm run view writes the two planning reports to views/. npm run docs writes project resource plans and staffing briefs to docs-out/. A hosted logo URL or data URL works across both output folders. Print the HTML to PDF when a document needs sharing. Protect the reports as business records.
